# Topic 02 Retrospective Short Version 2026-06-25

## 0. Purpose

本文是 `02_AFML_BIG_WINNER` 在 Episode 01-13 之后的短版 topic-level retrospective。它不是新实验结果，也不是 deployable 结论；它用于冻结当前研究事实，并给 Episode 14 的研究边界提供依据。

## 1. Topic-Level Fact

原始 thesis 仍然成立：

```text
BIG WINNER 是 episode lifecycle 问题，不是单日一步分类问题。
```

项目在执行上也保持了正确纪律：

- event-before-model；
- train-only selection；
- PIT / split / lineage audit；
- recall-first，但最终必须过 after-cost utility；
- failure / confirmation / continuation / winner 分层标签；
- 不用 validation / robustness 回头挑选事件、阈值或模型。

但 Episode 01-13 的统一事实也必须正面记录：

```text
confirmatory / deployable pass count = 0
experiments/completed/ = empty
```

这不等于“没有信号”。相反，多个 episode 反复看到过 ranking、recall、failure-side sorting、morphology readout 或 residual readout。真正反复失败的是：

```text
ranking / recall / probability readout
  -> after-cost full-denominator per-entry utility
```

这条转化链没有被打通。

## 2. Repeated Failure Pattern

短版归纳如下：

- 02 找到 reverse lifecycle sequence dominance，但只是 profile evidence。
- 03 / 04 把 profile 尝试变成 observable entry contract / candidate generator 后，coverage、bridge 和 clean return edge 不够。
- 08 / 09 / 10 / 11 证明 risk_on / fast-fail / failure-side sorting 有信号，但 winner retention、density、bad-side attribution 和 utility 不能同时过关。
- 12 证明 R-core 应降级为 recall stress pool；C0 / state-change 路线有局部 readout，但 12A7g 最终裁决为 C0 not separable，倾向 defense / participation context。
- 13 的 full-PIT native 重启确认：dense native token、compression directional filter、compression repair state、morphology residual、nonlinear model capacity、delayed entry、rule defense overlay 都没有把 lift 稳定转成 after-cost utility。

因此，当前 topic 的主要 blocker 不是单个数据源、单个模型或单个 cost 参数，而是：

```text
有信号的状态或排序，无法稳定变成可交易的 entry utility。
```

## 3. What This Does Not Prove

本 retrospective 不应被解读为：

```text
AFML thesis 错了。
A-share big winner early entry 一定不可行。
所有 event family 都已经穷尽。
只要降低 cost buffer 就能救回来。
```

更准确的边界是：

```text
dense state token search 已被 13A-13G 明确阻断；
C0 / compression repair 路线已被 12A7g 与 13A3/13C/13G 阻断；
post-hoc model capacity、delayed confirmation、rule overlay 不能在同一 selected state 上救回 utility。
```

但还有一个未被正面检验的空间：

```text
full-native sparse state-change event
  != dense daily state token
  != C0-derived repair state
```

Episode 13 的 `volatility_20d__bottom_20pct` 是 broad state token；13A3 的 `repair_range_participation_core_30` 是 composite state；13G 的 overlay 仍绑定同一个 selected repair event。它们没有等价测试“严格 first-trigger / reset / cooldown 的 full-native sparse state-change event”。

## 4. Strategic Decision

后续不应继续做第 14 个 dense state token，也不应继续在 13 的 selected compression-repair state 上调模型、调 k、调延迟或调 overlay。

可继续投入的唯一正向方向应改变问题定义：

```text
old:
  找一个 full-native state token，使 winner rate / ranking 变好。

new:
  找一个 full-native sparse state-change event，
  并检验它在严格 PIT cohort normalization 下
  是否能把 ranking 信号转成 after-cost full-denominator utility。
```

这同时吸收了 12A7 trailing-rank 报告的线索：whole-month / full-cohort rank 的 diagnostic upper bar 强于 trailing rank，说明“当前 cohort distribution 中的相对位置”可能有价值；但任何 whole-month / full-split rank 都有未来信息，只能作为 hypothesis，不可作为 evidence。

## 5. Next Episode

Episode 14 应作为一个新 episode 打开，而不是 13B：

```text
14_full_native_sparse_state_change_event_utility_preflight_v0
```

Episode 14 的第一阶段只做 preflight：

- 构造 full-native sparse state-change event family；
- 强制 first-trigger / reset / cooldown / event uniqueness；
- 保留 12A7g / 13A 的 PIT label 与 native universe lineage；
- 加入严格 PIT 的 cohort normalization arm；
- 用 50bps after-cost full-denominator utility 作为主 gate；
- 在任何 sequence mining、meta-labeling、bet sizing 或 backtest 之前做 stop / continue 裁决。

允许的正向结论只能是：

```text
one or more sparse state-change event families deserve a separate 14B confirmatory or sequence requirement.
```

不允许的结论是：

```text
deployable strategy found
meta-labeling ready
bet sizing ready
13B resurrected
```
