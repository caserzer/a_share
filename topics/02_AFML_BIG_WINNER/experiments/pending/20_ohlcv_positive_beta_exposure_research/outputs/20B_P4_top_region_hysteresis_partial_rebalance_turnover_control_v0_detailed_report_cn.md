### 4.1 连续顶部区域本身没有失败

无缓冲、完全再平衡的 `40/30/30` policy 实现：

```text

realized turnover = 37.11%
current-D8 = 38.76%

```

等权 `1/3,1/3,1/3` 的对应policy实现：


按冻结阈值做纯描述性检查时，75个policy中只有这两个policy同时跨过所有门槛。但它们不是预注册 primary，不能在看到结果后替换 primary 或升级为“支持”。这个结果只说明：**问题不在 D8-D10 累计池本身，而在叠加的部分再平衡和真实持仓slot机制。**

### 4.3 `rho=0.5` 是当前失败的主要触发器

在无缓冲、无cap的相同 `40/30/30` 结构下，把 `rho` 从1降到0.5：

```text
收益：          +40.40% -> +20.00%
事件月：         +5.54% -> -2.20%
realized turnover: 37.11% -> 10.43%
日均投入：       97.62% -> 66.02%
最差月投入：     81.57% -> 53.12%
平均排队新仓：    0.20 -> 44.60只/月
```

部分再平衡没有只减少“无效的小幅调权”，而是把应退出成员也长期保留为非零残仓。由于实际持仓定义是 `executed_shares > 0`、不允许忽略dust，每一只残仓继续占用一个真实持仓slot。新成员即使有正 hard target，也因没有slot而不能买入，未配置资本只能留在现金。

### 4.4 Primary 的40% cap实际上没有起作用

Primary 的20个过渡月中：

```text
cap绑定月份 = 0 / 20
minimum cap_scale = 1.0
最大 planned one-way turnover before cap = 28.03%
```

`F_MIX403030_XD7_R050_CNONE` 与正式 primary 的所有主要结果完全相同。因此不能把失败归因于“40% cap过紧”，也没有依据继续微调30%/40% cap。Primary 在进入cap之前，已经被 `rho=0.5 + slot cap` 限制。

| 1.00 | +30.86% | +0.60% | 18.68% | 89.41% |

虽然这些均值混合了exit floor、mix和cap交互，不能作独立因果估计，但方向与配对案例一致：更低的rho减少换手，同时系统性降低资本部署和事件响应。

`block_bootstrap_readout.csv` 当前只保存样本mean/std/count，method字段明确写为 `registered_not_used_for_selection`，没有10,000次block bootstrap的quantile/CI。因此本报告不提供置信区间、显著性或“统计胜出”结论。`pareto_frontier_readout.csv` 也没有实际的 `dominated_by_policy_ids`，所以本报告不把其中全部75行误写成正式Pareto frontier。

## 11. Findings 与研究含义

### Finding 1：组合层治理方向成立，但必须区分“退出”和“调权”

将预测排序与执行摩擦拆开是合理的。连续D8-D10、完全再平衡版本把realized turnover从D8的80.74%降至32.90%–37.11%，仍保留39.24%–40.40%的21月收益和正事件收益。

问题在于当前部分再平衡对所有delta使用同一个rho。对仍在目标池内的权重微调，`rho<1`可以降低噪声交易；但对已经 hard target=0 的退出仓，同样只卖一部分会留下占slot的残仓。两类交易的经济作用不同，不应继续使用完全相同的执行规则。

### Finding 2：持仓数量cap与无dust规则形成了路径依赖死锁

Primary 平均post-sell仍持有131.2只股票，离134上限只剩2.8个slot，却平均有33.45只新目标等待进入。现金无法解决slot不足，随后月份的目标响应继续延迟，形成：

```text
partial exit
-> 旧仓shares仍大于0
-> 旧仓继续占slot
-> 新目标排队
-> 现金无法投入
-> current-D8下降
-> 事件弹性损失
```

这条链条比交易成本、40% cap或少量涨跌停阻塞更能解释结果。

### Finding 3：D7缓冲不是主要失败源，但会稀释D8身份

D7缓冲在完全再平衡下把realized turnover从37.11%降到24.23%，且保持约98%投入，说明hysteresis本身有价值。但 current-D8 从38.76%降到27.03%，事件收益从5.54%降到2.96%。下一轮必须显式限制“缓冲成员可以占用多少D8 sleeve”，不能只冻结D8 sleeve名义权重。

### Finding 4：40% cap不是当前需要优化的参数

Primary 的cap从未绑定。继续测试30%/40%的细网格不会解决残仓占槽；根因在cap之前已经发生。只有在先修复退出和slot机制后，turnover cap才重新具有识别意义。

### Finding 5：收益损失主要是机会成本，不是成本后侵蚀

Primary 相对D8少付约3.68个百分点的成本拖累，却少获得约32.25个百分点的净收益。低换手节省是真实的，但远不足以补偿现金、低current-D8和事件月错配。

## 12. 下一轮可证伪方向

本轮不授权自动运行下一轮。若生成新 requirement，更合理的起点不是重训模型，也不是继续微调40% cap，而是预注册“退出与持有调权分离”的执行结构：

```text
1. hard_target = 0 的退出仓：
   优先卖至0，单独使用 exit budget；不使用普通 rho 留残仓。

2. hard_target > 0 的继续持有仓：
   权重微调允许 rho = 0.5。

3. 新进入仓：
   只在真实退出释放slot后进入；保持 sell-before-buy。

4. D7缓冲：
   冻结缓冲成员占D8 sleeve的最大比例，例如10%/20%，
   同时报告 sleeve-D8 与 current-D8。

5. 对照组：
   必须包含 F_MIX333_XD8_R100_CNONE、
   F_MIX403030_XD8_R100_CNONE、D7/rho1/no-cap 和 D8-only。
```

另一个可证伪方向是给真实持仓cap预留 transition headroom，例如 target count 与 actual cap 之间保留固定缓冲，但这会改变集中度和股票数风险，必须作为新contract单独冻结，不能在本轮结果上事后放宽134上限。

## 13. 不应得出的结论

- 不能说当前 primary 获得支持；正式状态是 `execution_fidelity_failed`。
- 不能把低换手本身当作成功；低换手伴随24%现金和D8资本不足。
- 不能从75个policy中事后宣布无缓冲完全再平衡版本为最优策略。
- 不能把五个事件月当作可预测regime标签或参数选择输入。
- 不能把P6 proxy写成成长、beta或未来波动预测。
- 不能据此重训模型；本轮主要失败发生在组合执行层。
- 不能授权20C、portfolio optimizer或部署。

## 14. 最终判断

本实验给出的最重要信息不是“32%–36%的设计换手估算错了”，而是：**设计层的相邻月成员重叠不能自动转化为真实可执行的低换手组合。** 当退出也被部分再平衡、实际持仓数又严格按shares>0计算时，较高的成员重叠会变成残仓累积，而不是平滑持有。

因此，下一步仍应保持 Full score 和bucket完全冻结，但组合层必须从“统一rho”升级为“退出、继续持有、新进入三类状态分别治理”。在此修复完成前，不应重训模型，也不应继续优化cap参数。
