# 持续评价与版本纪律

## 已可执行的评价快照

先产生独立版本的本地观测重放及E02B评价，再执行：

```bash
python topics/02_AFML_BIG_WINNER/experiments/pending/34_industry_price_observation_radar/src/v3_candidate_evaluation_snapshot.py   --evaluation-dir <新E02B评价目录>   --comparison-dir <对应比较与后续收益目录>   --out <尚不存在的新快照目录>
```

脚本校验来源收据，不覆盖已有快照，完整保留所有唯一NEW和父子分母。已实际运行的快照为outputs/v3_candidate_evaluation_20261021。此命令汇总已有评价，不负责采集、训练或生成新日期信号。

## 每次新本地数据后的顺序

1. 固定价格/分类/市场版本和截至日；审查价格链、目录与known_at边界。没有新本地数据就不伪造新日期。
2. 用冻结特征和正确年度模型计算当时分数。跨年需按已冻结成熟规则拟合新年度模型，未准备好则明确不可推断，不能静默沿用未知模型。
3. 从同一起点按时间重放，或加载已经核验的完整池、入池周、弱势计数、冷却及身份状态；不能把新期当成空池重新开始。
4. 输出全目录与事件账；对全部旧前缀比对信号/事件，差异必须注明数据修订或规则变更，不覆盖旧版本。
5. 仅在评价侧重建成熟过程。未成熟/未知单列，首次误报保留。过程版本改变时单独做归属迁移，不能把标签修订称为方法提升。
6. 运行全量E02B和上述评价快照；按新增、持续更新、父/子、及时/迟到、年度/市场分层呈现，保留20/60/90/180日后续路径及缺口。

## 预警与复核

数据断链、目录缺失、模型年份不匹配、容量超限、重复主归属或旧事件无说明变化，均触发停止该版本交付和核查；不把这些故障记成策略失败。价格证据消失依冻结池规则更新/退出，不能因评估不理想而临时改标签。

约50%有效只作观察参考：下降时报告成熟分母、未知和时间分层，不以小样本单周波动自动改模型。覆盖、及时性、质量和研究负担一起复核，不按单一收益或F1调参。

## 当前操作边界

已完成历史观察交付与评价快照。未来日期的端到端增量生成及冷启动/续接一致性尚需专门核验；没有部署、自动任务或自动训练。不能将这份规范本身当作已运行的持续生产系统。
