# R18 版本化观察与成熟标签

本轮验证能否保留观察时的来源版本，并在后续评价时隔离成熟结果。结果：两个真实本地历史截面已完成不可覆盖的快照、幂等重跑和独立标签评价；前瞻记录为0。工程流程成立，不代表预测有效或已部署实时更新。

## 固定协议与实际结果

协议为 `protocols/r18.json`。2026-06-30与2026-09-30各保留SW2021目录511行，价格可用418行，另隔离目录外代码850412.SI一行，不猜测分类。一级、二级、三级分别排名，价格评分只使用当日及此前量价特征；机制、预期、持仓拥挤和经济阶段明确记为未核验。

截至2026-10-21，六月快照在20/60日各有418行成熟、13行身份缺失、80行缺价或路径不连续；九月两期限各511行等待足够交易日。缺失行没有删除或填零，价格是否可用另行保留。入场为观察后下一交易日收盘，退出为入场后20/60交易日收盘。

## 来源与更新规则

`src/versioned_observations.py` 将行情、目录、协议及特征代码复制到按SHA-256命名的本地来源库；快照和结果分别封存。相同来源和日期重复运行返回原版本，不改变原清单。新来源版本生成新评价，记录观察日前价格修订数，不回写旧观察。

`capture --intent forward`只允许上海当前日期15点后且来源有该日数据，不能把历史回放追认为前瞻。实际捕获时间被记录，评价还检查入场时点是否在捕获之后。这只是时序门槛，无法认证供应商首次发布、历史成分及复权修订为严格PIT。

从项目目录使用上级虚拟环境Python执行：

```bash
python src/versioned_observations.py capture --asof 2026-09-30 --intent historical
python src/versioned_observations.py evaluate --bundle <完整快照目录> --asof 2026-10-21
python src/versioned_observations.py verify --bundle <完整快照目录>
```

输入可通过 `--daily`、`--market`、`--catalog`、`--store` 显式指定。先验证新来源时间、身份和覆盖，再捕获；目录外身份隔离，旧记录不改。`outputs/r18/replay_receipt.json` 给出实际快照与评价目录。`src/replay_update_flow.py` 重放本轮工程验收，`src/verify_updates.py` 校验清单、分母及来源。

六项新增测试覆盖前缀不变性、目标字段隔离、目录外身份隔离、成熟边界/断价、禁止前瞻倒填、封存损坏识别、幂等与来源修订分离。源码测试中覆盖多项断言，不以测试数量证明经济有效。
